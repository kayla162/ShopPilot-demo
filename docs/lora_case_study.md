# 讓 1.5B 模型學會用工具：賣家問答系統的 LoRA 微調紀錄

> ShopPilot 是我替自己的蝦皮賣場做的分析工具。這篇記錄「AI 問答」怎麼從 59% 做到 96%：怎麼決定做法、怎麼產生訓練資料、怎麼公平比較，以及三版訓練資料之間怎麼選。
> 程式碼：[ShopPilot-demo](https://github.com/kayla162/ShopPilot-demo) · 模型：[Hugging Face](https://huggingface.co/kayla162/shoppilot-qwen2.5-1.5b-tools-lora) · [English version](lora_case_study_en.md)

## 1. 問題：賣家想用白話問數字

賣家常問的是「這件本期賣了幾件？」「長褲裡哪件最熱銷？」「現在最該先處理什麼？」。答案都在報表裡，但散在好幾個 Excel 檔。

有三個限制決定了做法：

- **數字不能錯。** 賣家會照著補貨、改價。所以數字全部由程式算，AI 只負責把算好的結果寫成白話；回答裡出現資料沒有的數字，就擋下不顯示（數字檢查）。
- **要在一般筆電上跑。** 賣場資料不想送到外部 API，線上 demo 也只有免費主機。所以選 Qwen2.5-1.5B-Instruct，用 llama.cpp 的 4-bit 量化在 CPU 上推論。
- **資料是結構化的數字，不是文件。** 所以不用 RAG（檢索文字段落），而是讓模型呼叫工具查詢。工具由程式執行，回傳的就是正確的數字。

## 2. 兩種做法的起點：資料表 89%、工具呼叫 59%

**資料表做法**每題都送一份約 5 千字的賣場資料（全店摘要、各類別、銷量前幾名、問題裡提到的商品），模型從表裡找答案。

**工具呼叫做法**給模型 7 個工具：全店摘要、類別排行、銷量排行、查商品、搜尋商品、側欄選的商品、最該先處理的事。模型自己決定查什麼，只看到它要的那一小段資料。

評估用 141 題：3 個賣場（示範賣場＋兩家真實賣場）各 32 題原本的題目，加 15 題長尾商品題。題目和標準答案都由程式從同一份資料算出，所以能自動評分，換賣場、換期間都能重跑。

| 做法（Q4 量化、CPU） | 141 題 |
|---|---|
| 資料表 | 125（89%） |
| 工具呼叫 | 83（59%） |

工具呼叫的錯誤很集中，看 `details.csv` 一題一題分類：

- **選錯工具。** 問「本期賣了幾件」，去查銷量排行，而不是查那個商品。
- **不查側欄的商品。** 賣家在畫面側欄選了一個商品，問「這件賣了幾件？」，模型不知道「這件」要用「側欄選的商品」工具。側欄題 0/18。
- **拿到結果還說沒有。** 工具已經回傳了數字，回答卻是「目前的資料沒有」。

這些都是「不會用工具」，不是「不懂中文」或「算錯」，正好是微調擅長解決的問題。

## 3. 訓練資料：用評估的同一套程式產生，不用人工標註

評估已經能從資料算出每題的標準答案。同一套程式往前一步，就能產生完整的示範對話：

> 問題 → 正確的工具呼叫 → 工具真的執行後的回傳 → 只用回傳數字寫成的標準回答

- 13 種題型，每種有好幾種說法；v1 共 662 筆。
- 每筆的標準回答都先通過數字檢查才收。
- **不對著考題訓練：** 訓練賣場用另外的亂數種子產生，和開發集、評估的示範賣場、真實賣場都不重疊；評估、開發集、口語題的原句都不收（有測試檢查）。
- 每個題型都要真的產生得出資料，也有測試檢查。這個測試是踩過坑才加的：工具的回傳格式改過之後，「最該先處理的事」的產生器讀舊欄位，那個題型悄悄消失了好幾版。

## 4. QLoRA：6 GB 筆電顯示卡

- 原本的權重用 4-bit NF4 存，LoRA（rank 16、alpha 32，q/k/v/o/gate/up/down）用 bfloat16 訓練，只訓練 1,846 萬個參數（約 1.2%）。
- 只算回答的 loss；只對要算 loss 的位置算詞彙表的 logits；開 gradient checkpointing。
- RTX 3060 Laptop（6 GB）1 個 epoch 43.7 分鐘，顯示卡記憶體最高 2.1 GB；驗證 loss 0.52 → 0.004。

## 5. 公平比較：同樣的精度，只差在有沒有 LoRA

第一次比較有個問題：微調後的模型用 transformers（bfloat16）跑，原本的模型用 llama.cpp（4-bit）跑，差距有一部分可能來自精度。

所以我寫了 `scripts/export_lora_gguf.py`：自己讀 safetensors，照 llama.cpp 的張量命名寫成 GGUF adapter，直接套在 Qwen 官方的 Q4_K_M 模型上。兩邊都是同一個 4-bit 模型、同一份 prompt、同一台 CPU，只差在有沒有 LoRA。

| 141 題 | 微調前 | 微調後 |
|---|---|---|
| 合計 | 83（59%） | **135（96%）** |
| 問側欄選的商品 | 0/18 | **18/18** |
| 商品銷量 | 3/15 | **15/15** |
| 長尾商品的銷量 | 0/15 | **15/15** |
| 最該先處理的事 | 1/3 | **3/3** |

- 兩邊答同一批題目，所以用成對的 McNemar 精確檢定：p < 10⁻¹¹。
- 訓練資料全是程式產生的示範服飾賣場，兩家真實賣場（服飾、保養品）都沒看過，照樣是 98% 和 91%。
- 141 題只有 1 題答錯，其他 5 題沒答對的是回答「資料沒有」。

## 6. 三版訓練資料，依「答錯的方式」選版本

v1 還有沒學到的題型，所以照錯誤分析又做了兩版：

| 訓練資料 | 加了什麼 | 141 題 | 答錯（不含回答資料沒有） |
|---|---|---|---|
| **v1（發布）** | 每個題型一個問題、單一工具 | **135** | **1** |
| v2 | 一題問兩件事、「【品牌】品項 品項」長名稱 | 126 | 2 |
| v3 | 口語前後綴、名稱後半段、各種代名詞的側欄題、前幾名和類別合計 | 135 | 6 |

**v2：學會新題型，舊題型卻退步了。** 「全店銷量最高的是哪個？它的價格是多少？」從 0/3 進步到 3/3，但側欄題從 18/18 掉到 6/18。

原因在訓練資料：一題問兩件事的題目裡，「它」指的是題目前半的商品。模型學到「它＝前面提過的商品」，連單獨問「它／這個商品」的時候也不查側欄了，改去查一個叫「這個商品」的商品。

**v3：補上衝突的例子。** 加了各種代名詞單獨出現的側欄題，兩種題目都答對了（18/18、3/3），141 題和 v1 一樣是 135 題。

**但答錯的方式不一樣。** v3 答錯的 6 題，全是自信地報出錯的銷量，例如把 28 件說成「3.88 件」。這些數字在工具回傳的結果裡找得到，所以數字檢查擋不下來。v1 沒把握時會說「資料沒有」。

對賣家來說，報錯數字比說不知道危險得多，所以發布 v1。v2、v3 都可以用 `scripts/train_lora.py --data-version 2|3` 重現。

## 7. 評估設計：開發集和最終測試分開

v2、v3 的訓練資料是看了 141 題和口語題 A 的錯題才改的，所以這兩組題目對 v2、v3 不再是「沒看過的題目」。我用兩個方法處理：

- **口語題 A／B。** 兩組都是手寫的賣家口語，在示範賣場各 30 題，標準答案一樣由程式算出。A 拿來做錯誤分析，之後就當開發集。B 在 v3 有任何結果之前寫好，只在最後跑一次，不拿來挑改法。
- **大模型對照。** 透過 OpenAI 相容的 API 接本機 Ollama 的 Qwen3 8B（關掉思考模式），用同樣的工具和 prompt。

| 做法 | 141 題（95% 信賴區間） | 口語題 B |
|---|---|---|
| 資料表 · 1.5B | 125（89%，82–93%） | 20/30 |
| 工具呼叫 · 1.5B | 83（59%，51–67%） | 16/30 |
| **工具呼叫 · 1.5B＋LoRA v1** | **135（96%，91–98%）** | **21/30** |
| 工具呼叫 · Qwen3 8B | 133（94%，89–97%） | 25/30 |

**怎麼解讀這些數字：**

- 141 題上「微調前 → 微調後」的差距非常確定（p < 10⁻¹¹），微調後和 5 倍大的 Qwen3 8B 相當。
- 資料表 vs. 工具呼叫＋LoRA 在 141 題差 7 個百分點，p = 0.052，在顯著的邊緣。所以兩種做法都保留，用設定切換。
- 口語題 B 只有 30 題，信賴區間很寬：幾種 1.5B 做法彼此之間、和 Qwen3 8B 之間（p = 0.22），都沒有統計上的差異。口語題比較適合用來看「哪種問法會錯」，不適合拿來排名。

正確率都附 Wilson 信賴區間；兩種做法答同一批題目時，用 McNemar 精確檢定和成對 bootstrap 比較（`python -m shoppilot.llm.eval_stats`）。

## 8. 下一步：賣家實際的提問

到目前為止，題目都是程式產生，或是照賣家口吻手寫的。下一步是真實的提問：

- 「AI 問答」每一題都會記下問題、回答和當時的資料期間，賣家可以在回答下面按 👍／👎。「AI 監控」分頁會照模型和做法，顯示賣家判斷的答對率。
- `python -m shoppilot.llm.real_eval export` 把紀錄匯出成題目檔。補上標準答案之後（可以用和口語題相同的寫法，答案從資料算），`python -m shoppilot.llm.qa_eval --real` 就能換模型、換做法，重跑同一批真實提問。
- 紀錄只存在賣場自己的資料庫，不進版控，也不會匯出到公開版。

## 9. 學到的事

1. **先分類錯誤，再決定要不要微調。** 59% 的錯誤幾乎都是「不會用工具」，這種問題用程式產生的示範對話就能教，不需要更大的模型。
2. **評估程式就是最好的資料產生器。** 能算出標準答案，就能產生示範對話；兩邊用同一套程式，訓練和評估的定義不會悄悄分岔。
3. **公平比較要控制精度。** 把 LoRA 轉成 GGUF、套在同一個量化模型上，差距才能只歸因於微調。
4. **加資料會帶來衝突。** 新題型的訓練資料可能和舊題型互相矛盾（v2 的「它」），每加一類資料都要看各題型的分數，不能只看總分。
5. **總分一樣時，看答錯的方式。** v1 和 v3 都是 135 題，但一個會說不知道，一個會報錯數字；選版本要看哪種錯誤對使用者比較危險。
6. **小樣本要誠實。** 30 題的差距常常不顯著，報告時附信賴區間和檢定，比只放正確率更有說服力。
